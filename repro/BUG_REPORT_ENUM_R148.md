**结论先行：`{4,4,2}` 的置放数应为 1575，不是 1260。若数学侧 Σ₁₀
账本用的是 1260，该账本需要修正。**

## 1. 缺陷

`block_classes.py::set_partitions_by_sizes` 的去重技巧
"把最小剩余元强制放进当前块"，判据写的是**下一个尺寸等于 s**：

    force = bool(rest) and rest[0] == s          # 错

正确条件是**所有剩余尺寸都等于 s**——只有那时最小元才必然落在
一个 size-s 块里：

    force = bool(rest) and all(x == s for x in rest)      # r148 修正

`{4,4,2}` 排序为 `[4,4,2]`：首块 s=4、rest=[4,2]，旧判据取真，
把元素 0 强行塞进一个 4-块，**"0 在 2-块"的全部分拆被整体丢弃**。

漏失量可精确核对：9（0 的搭档）× 35（余 8 点分两无序 4-块）= **315**，
而 1260 + 315 = 1575，分毫不差。

## 2. 影响范围（已逐类暴力回归）

修复后对 18 个类逐一核对多项式系数 `n!/∏sᵢ!/∏mⱼ!`，**全部一致**：

    {2,2,2} {2⁴} {5,2} {6,2} {4,4} {2,2,4} {2⁵} {2,2,5} {4,2,2,2}
    {5,4} {7,2} {6,2,2} {4,4,2} {3,3,4} {4,4,4} {5,5} {8,2} {6,4}

**受影响的只有 `{4,4,2}`**：它是已算类中唯一"等大小块尺寸 ≥3 且未覆盖
全部元素"的形状。其余类要么等大小块都是 size 2 且排在末尾（判据碰巧
取到正确值），要么根本没有等大小块。

**注意 `{3,3,4}`、`{4,4,4}`、`{5,5}` 同属高危形状**，若 Σ₁₀ 及以上
账本涉及它们，请一并按修复后的枚举器复核。

## 3. 该缺陷本应被两道现成检查抓住

作废运行的轨道 size 谱是 `{16:60, 8:34, 4:7}`。而 **16 ∤ 20**、**8 ∤ 20**
——D₁₀ 阶为 20，**轨道大小必须整除群阶**，这两个尺寸几何上不可能存在。

修复后：`{20:60, 10:34, 5:7}`，全部整除 20，合计 1575，仍是 101 个轨道。
旧尺寸恰为真值的 4/5，与漏失机制完全吻合。

`g_ledger.py` 同时含**闭式置放数**与 **size 整除 2b** 两道检查，
任何一道都能当场逮住。**两道都没有运行，因为 `{4,4,2}` 从未被列入门的
类表**——这是计算侧的失误：入库时给它写了 orbits/values/RUN.md，
却漏了把它加进门。**门只保护它被告知要保护的东西。**

已加入门表并登记为 `WITHHELD`，输出中有名有姓。
