### 一个必须记录的比对错误（我的）

首次跑判据时 `{2,2,4}` 与 `{4,4}` 大幅 FAIL（2.5e-3 / 3.8e-4），只有 `{6,2}` 过。
**没有接受这个结论**——同一套机器、同一内核，三个类不该只有一个对，
这个模式本身就是信号。

根因：**我按轨道序号对齐两侧数据**，但阶梯脚本（`L.orbits()` 的枚举序）
与精确链（`block_classes.py` 的 `(-size, rep)` 序）**排序不同，且对同一轨道
选的代表元也不同**。

两步修正：(i) 改按代表元匹配 → `{4,4}` 匹配上 3 个，误差立刻降到 3.85e-07，
诊断确认；(ii) 改按**二面体轨道规范形** `min(orbit(...))` 匹配 → 三个类
22/22、7/7、4/4 全匹配，全部通过。

顺带修一个报告 bug：0 匹配时 `worst` 保持 0.0 会被**误判为 PASS**；
现在匹配数不足直接判"判据不适用"。

**教训入册**：跨工具链比对必须用**内容规范形**做键，不能用序号；
且必须断言"匹配数 = 期望数"，否则空比对会假装通过。

## 2quinquies. O5 高统计模型测量 + F-PRED-RAT-9/10 + k=10 定价（r138）

### O5：Σ₉/Σ₁₀ 的高统计测量 —— 精度超要求 5 倍

工具：`phase3/o5_sigma.py`。模型测度 = CUE 点上单位圆 Vandermonde Gram 的
ESD（与 `christoffel_pricing.sample_spectrum` 同构造）；测的是**中心矩**
`Σ_j = E(λ−1)^j`，正是再中心化恒等式 `G̃/(Lℓ₁) = I + P` 所钉定的量。

参考采样器在单进程里循环样本；因其 RNG 是**逐样本流**
（`default_rng((seed,N,k))`），样本独立且可复现，故循环可干净分片。
每个 worker 返回**逐样本**中心矩，误差棒按**样本**（而非特征值）自助
——同一样本内的特征值强相关，有效样本数是 CUE 抽样数。

## 3bis. 调度事故与修正（前向记录）

**事故**：把 `{6,4}` 排在 220 的队列首位，`--jobs 120`。`{6,4}` 每轨道
28,132 个 F-CYC 项、R¹¹，每 worker 的 memo 表涨到 ~1.8 GB，
120 × 1.8 = 216 GB / 251 GB ⟹ 进 swap 31 GB，全部 worker 阻塞在 I/O，
load 从 121 掉到 2.3，**1 小时 27 分 0 轨道产出**。

**根因**：调度按名字直觉，没算成本。每轨道 F-CYC 项数 = **各大块项数之积**：

| 类 | 项/轨道 | | 类 | 项/轨道 |
|---|---|---|---|---|
| {4,2,2,2} | 26 | | {5,4} | 3,900 |
| {2,2,5} | 150 | | {7,2} | 9,366 |
| {4,4,2} | 676 | | {5,5} | 22,500 |
| {6,2,2} | 1,082 | | {6,4} | 28,132 |
| | | | {8,2} | 94,586 |

**修正**：队列改按成本升序，并给重类设 job 上限（memo 表大的少开 worker）；
重类先跑单轨道探针。修复后 swap 归零，`{4,2,2,2}` 半小时出 94/190 轨道。

**教训入册**：
1. `memo 表 × worker 数` 才是内存的真实约束，不是任务数；
2. `pkill -f <pattern>` 会匹配到自己的 ssh 命令行而自杀（连续几次 exit 255
   即此），须用 `pkill -f "[p]attern"` 防自匹配；
3. 启动后必须**回读日志**确认（`ps` 计数在进程启动瞬间是对的，程序随即退出
   也看不出来——230 漏传 `run_k10.py` 那次就是这样丢了 20 核工时）。
