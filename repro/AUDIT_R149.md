## 二、阻断级缺陷（1 项，建议立即修）

### 2.1 `run_all.sh light` 现在会在第一步整体中止

`light()` 开头是 `set -e`，而**第一条命令**是需要 `sympy` 的
`g_span_t222.py`：

    light() {
      set -e
      "$PY" "$HERE/gates/g_span_t222.py"     # slow sympy gate
      "$PY" "$HERE/engines/t222_exact.py"
      ... 其余八个类的全量重算 ...

**本机实测 `import sympy` → ModuleNotFoundError。** 在任何未装 sympy
的机器上，`run_all.sh light` 会**立即退出，后面八个类的重算一个都不跑**。

这不是假设：**220 连 numpy 都没有**（RUN.md 已写明"刻面链可跑、
阶梯链不可"），sympy 更不会有；而 220 正是跑重类的主力。

在此之前，light 层除可选的 gmpy2 外**无第三方依赖**，这是它能在
异构机群上通跑的原因。本次改动把一个**硬依赖**放在了最前面。

**建议三选一**：

1. 把 `g_span_t222.py` 移到 light 层**末尾**（最小改动，保住前面八项）；
2. 在门内做 `try: import sympy / except ImportError:` → 打印
   `NOT-APPLICABLE` 并按 REPRO_SPEC §3 退出非零，由调用方决定是否致命；
3. 把它单列为 `run_all.sh derive` 层，不混进 light。

**我倾向 2 + 1 并用**：门自述依赖缺失（可诊断），且不挡住其余重算。
